# ZKTeco HRMS / Attendance

Laravel app for ZKTeco biometric attendance, leave, roster, and payroll.

## Requirements

- PHP 8.1+ with `sockets` extension (LAN device sync)
- MySQL / MariaDB (production) or SQLite (tests)
- Composer
- Scheduler / cron for `zkteco:sync-all`

## Setup

```bash
composer install
cp .env.example .env
php artisan key:generate
# Configure DB_* and APP_URL in .env
php artisan migrate
php artisan db:seed   # if you use the default seeder
php artisan serve
```

Create the first user via seeder/tinker, then use **Users & Roles** in the UI.

### Mail (password reset & notifications)

```env
MAIL_MAILER=log          # local: links appear in storage/logs
# or SMTP for production
MAIL_MAILER=smtp
MAIL_HOST=...
MAIL_PORT=587
MAIL_USERNAME=...
MAIL_PASSWORD=...
MAIL_FROM_ADDRESS=hr@yourcompany.com
MAIL_FROM_NAME="${APP_NAME}"
```

## ZKTeco devices

### Option A — LAN pull (UDP/TCP)

1. Add the device under **Devices** (IP + port, usually `4370`).
2. Run sync from the UI, or schedule:

```bash
php artisan zkteco:sync-all
```

Cron (every minute Laravel scheduler):

```cron
* * * * * cd /path/to/zkteco-project && php artisan schedule:run >> /dev/null 2>&1
```

### Option B — Cloud ADMS / Push (`/iclock/...`)

Point the device Cloud Server to your public `APP_URL` (port 80/443). Endpoints:

| Path | Purpose |
|------|---------|
| `/iclock/cdata` | Handshake + attendance push |
| `/iclock/getrequest` | Device polls for commands |
| `/iclock/devicecmd` | Command replies |

Also: `POST /api/zkteco/attendance` for JSON push (stays public). See **Devices → Push setup**.

## Roles

| Role | Access |
|------|--------|
| Super Admin | Everything, including users & audit |
| Admin | Operations + settings + audit (not users) |
| HR Manager | Employees, leave, payroll, reports |
| Manager | Own **department** only: reports, attendance edits, leave |
| User | Employee portal when linked to an employee |

Link a login to an employee under **Users & Roles** to enable **My portal** (attendance, leave requests, payslips).

Managers must be linked to an employee that has a **department**; otherwise their team lists stay empty.

## API (Sanctum)

```http
POST /api/login
{ "email": "...", "password": "..." }

Authorization: Bearer <token>
GET  /api/employees
GET  /api/devices
GET  /api/attendance-logs
POST /api/logout
```

## Key features

- Attendance reports + day punch edit
- Summary reports (late / absence / leave / overtime)
- Leave types, balances, holidays, approvals + email notify
- Roster / shifts
- Payroll generate, lock, payslip PDF, CSV export
- Audit log (punches, leave, salaries, users)
- Password reset

## Tests

```bash
php artisan test
```

Uses in-memory SQLite (`phpunit.xml`).

## Production notes

- Set `APP_URL` to the public HTTPS URL devices and emails use.
- Keep ADMS/push endpoints reachable without auth (devices cannot log in).
- Lock payroll months after review so they cannot be regenerated by mistake.
